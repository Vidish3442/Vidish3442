# 🚀 Featured Projects
## 📈 [AI-Powered Stock Screener and Advisory Platform](https://github.com/Vidish3442/AI-Powered-Stock-Screener-and-Advisory-Platform)

**Tech Stack:** Python · FastAPI · Streamlit · MySQL/TiDB · OpenRouter · yfinance · GitHub Actions

[GitHub Repository](https://github.com/Vidish3442/AI-Powered-Stock-Screener-and-Advisory-Platform) · [Live App](https://ai-powered-stock-screener-and-advisory-platform.streamlit.app/) · [Screenshots](https://github.com/Vidish3442/AI-Powered-Stock-Screener-and-Advisory-Platform/tree/main/img) · [Ingestion Schedule](https://github.com/Vidish3442/AI-Powered-Stock-Screener-and-Advisory-Platform/blob/main/INGESTION_SCHEDULE.md)

Built an AI-powered stock screening and advisory application that lets users explore financial data using natural-language queries, alongside portfolio tracking and metric-based alerts.

**Key Features & Engineering Work**
- **Natural-language screening:** Integrates an LLM through OpenRouter to interpret investment queries and convert them into structured screening criteria.
- **Backend architecture:** Separates backend API functionality from the Streamlit user interface using FastAPI.
- **Query processing:** Uses application-side validation and SQL query generation to process structured screening requests.
- **Financial data ingestion:** Organizes data ingestion separately and uses GitHub Actions for scheduled workflows.
- **Database support:** Uses MySQL/TiDB for structured financial data, with database index scripts included in the repository.
- **Testing:** Includes a dedicated `tests/` directory for testing application components.
- **Application features:** Supports portfolio tracking and metric-based alerts.

**Repository Structure**
- `backend/` — Backend application logic
- `ingestion/` — Financial data ingestion workflows
- `tests/` — Application tests
- `.github/workflows/` — Automated GitHub Actions workflows
- `img/` — Project screenshots
- `add_indexes.sql` — Database index definitions
- `INGESTION_SCHEDULE.md` — Data refresh schedule

**Focus Areas:** LLM Integration · Python Backend Development · Natural Language to SQL · Data Engineering · Database Design

*Educational project, not financial advice.*

## 🩺 [Diabetic Retinopathy Detection](https://github.com/Vidish3442/Diabetic-Retinopathy-Detection)

**Tech Stack:** Python · TensorFlow/Keras · CNN · Flask · APTOS Dataset

[GitHub Repository](https://github.com/Vidish3442/Diabetic-Retinopathy-Detection)

Developed a Computer Vision application that classifies retinal fundus images into diabetic retinopathy severity categories using deep learning.

**Key Features & Engineering Work**
- **Image classification:** Trained CNN-based models to classify retinal images into five categories: No DR, Mild, Moderate, Severe, and Proliferative DR.
- **Image preprocessing:** Applied image resizing, normalization, and augmentation as part of the training workflow.
- **Model evaluation:** Evaluated model performance using classification accuracy and loss.
- **Web interface:** Built an image-upload and inference interface that displays the predicted category and confidence score.
- **Model deployment:** Kept model weights outside the Git repository because of file-size constraints.

**Project Focus:** Computer Vision · Deep Learning · Image Classification · Model Evaluation

*Research and learning project; not a clinically validated diagnostic tool.*

## 📄 [Engineering Document Intelligence System](https://github.com/Vidish3442/Engineering-Document-Intelligence)

**Tech Stack:** Python · RAG · FAISS · PyMuPDF · Tesseract OCR · LLM APIs

[GitHub Repository](https://github.com/Vidish3442/Engineering-Document-Intelligence)

Developed a document intelligence workflow for extracting, retrieving, and answering questions about technical information contained in engineering documents, including PDFs and scanned files.

**Key Features & Engineering Work**
- **Document processing:** Extracts text from PDFs using PyMuPDF and processes scanned content using Tesseract OCR.
- **Information retrieval:** Uses retrieval-based methods to identify document passages relevant to a user's question.
- **Vector search:** Uses FAISS for similarity-based retrieval of relevant document content.
- **LLM integration:** Uses an LLM API to generate responses from retrieved document context.
- **Source-grounded responses:** Designed to connect generated answers with information retrieved from the source documents.
- **End-to-end workflow:** Combines document extraction, retrieval, and language model integration into a question-answering application.

**Project Focus:** Document Intelligence · Retrieval-Augmented Generation (RAG) · OCR · Information Retrieval · LLM Applications
